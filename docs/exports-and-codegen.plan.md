# Callspec exports and consumer codegen

Extend callspec so the **`callspec.json` contract** is not only route RPC shapes + generated HTTP client, but also an **explicit registry of shared runtyp schemas** for frontend validation and types — without importing the backend package.

Related: [Logfox callspec migration](../../../api-service/docs/callspec-migration.plan.md).

---

## Problem

Today:

- `emitCallspec` serializes each route's `input` / `output` via `runtyp` → JSON Schema (inlined).
- Client generator emits **per-route TypeScript types** + `ApiClient` only.
- Composed preds (e.g. `logQueryFilter` inside `searchLogsInput`) **lose their name** — consumers get `SearchLogsInput` but not a reusable filter pred.
- Frontend teams duplicate runtyp preds or import the server npm package (Express/pg leakage).

---

## Goals

- **`defineSpec({ exports })`** — named registry of runtyp preds emitted to `callspec.json`.
- **Validator codegen** — emit runtyp `Pred` objects + `Infer` types for routes and exports.
- **Documentation** — README and docs prominently position callspec as **shared validation/types**, not "client generator only".
- Browser-safe output: generated files import **`runtyp`** + **`callspec/client`** only.

## Non-goals

- `$ref` / deduplicated schema graph in v1 (optional follow-up).
- Generating React hooks or form components.
- Replacing runtyp on the server — exports are the same preds, serialized for consumers.

---

## `defineSpec` API

```typescript
defineSpec({
  meta: { … },
  routes: { searchLogs: defineRoute({ input: searchLogsInput, … }) },
  exports: {
    logQueryFilter,
    notificationRule,
    appName,
    env,
  },
  authenticate: …,
})
```

Rules:

- **Keys:** camelCase export names → codegen emits `logQueryFilter` pred + `LogQueryFilter` type.
- **Values:** `Pred<any>` only (must round-trip through `toJsonSchema`).
- **Overlap with routes allowed** — same pred reference in route input and exports.

---

## Document shape (`callspec.json`)

```json
{
  "callspec": "1.0",
  "info": { "title": "…", "version": "…" },
  "exports": {
    "logQueryFilter": { "type": "object", "properties": { … } },
    "notificationRule": { … }
  },
  "routes": {
    "searchLogs": {
      "input": { "type": "object", "properties": { … } },
      "output": { … }
    }
  }
}
```

v1: exports and route schemas may duplicate bytes. v2: optional `$ref` to `#/exports/logQueryFilter`.

## Codegen

### Existing: `generateClientFile` → `api.ts`

Unchanged: route methods, input/output/error types, `ApiClient`.

### New: validator emit

CLI:

```bash
callspec ./callspec.json --output src/generated/api.ts
callspec ./callspec.json --output src/generated/validators.ts --validators
```

Or single invocation with two outputs (TBD in implementation).

Generated `validators.ts`:

```typescript
/** Generated by callspec — do not edit. */
import { predicates as p, type Infer } from 'runtyp';

export const logQueryFilter = p.object({ … });
export type LogQueryFilter = Infer<typeof logQueryFilter>;

export const searchLogsInput = p.object({ … });
export type SearchLogsInput = Infer<typeof searchLogsInput>;
```

Route preds named `{routeName}Input`, `{routeName}Output` (or reuse existing `SearchLogsInput` naming from client gen for parity).

Implementation options for pred reconstruction:

1. **JSON Schema → runtyp emit** (codegen string of `p.object({…})` calls) — no runtime schema parser in browser.
2. **Dual emit from TS source** in backend CI (pred .ts → validators.ts via ts-morph) — heavier, bypasses callspec.json for preds only. Prefer (1) for single document truth.

---

## What can go in `exports`

| Allowed | Examples |
|---------|----------|
| Object / scalar / union preds | `logQueryFilter`, `notificationRule`, `appName`, `env` |
| Nested building blocks | `discordDeliveryMethodConfig` |
| Shared error `data` preds | Reused across routes |

| Not allowed | Why |
|-------------|-----|
| Handlers, `authenticate` | Server runtime |
| UI-only shapes | Belong in frontend |
| Preds `toJsonSchema` can't express | Weak contract |
